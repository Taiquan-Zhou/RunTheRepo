## Decision

C0 proves that the current total default of 2,048 MiB is sufficient and does
not authorize a larger public default. It independently disproves the current
1:8 cloned-workspace mapping at that default: the same hard total changes from
repeatable ENOSPC to full healthy Boot when the allocation is
`R=1, D=1919, W=128`.

The allowed implementation boundary is therefore a TDD correction to the
existing private allocation calculation and its focused tests. It must preserve
the single public `SandboxPolicy.disk_mb`, the exact hard sum, official floors,
subprocess environment enforcement, fail-closed insufficient-budget behavior,
and all frozen architecture and product contracts. No DiskManager, provider,
public field, Compose mutation, repository-specific branch, or default-total
increase is authorized.

An independent design review rejected a permanent 128 MiB workspace cap because
larger user budgets would then be unable to accommodate larger repositories.
The accepted private mapping is a calibrated 128 MiB platform with continued
1:16 growth for larger budgets:

```python
workspace_mb = max(
    WORKSPACE_FLOOR_MB,
    min(disk_mb // 8, 128),
    disk_mb // 16,
)
```

This retains `7 -> (1,1,5)` and `512 -> (1,447,64)`, implements the verified
`2048 -> (1,1919,128)`, and ensures a larger `4096 MiB` policy grows the cloned
workspace to `256 MiB` instead of freezing it at 128 MiB. Sixty-four MiB is a
proven clone-compatible value for three frozen repositories, not a claim that
all repositories or runtime stages need only 64 MiB.
