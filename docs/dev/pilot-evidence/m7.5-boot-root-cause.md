`sbx policy ls --type network --json` showed an immutable global
`default-deny-all` rule for `**`. `sbx policy check network --json` independently
confirmed that public image registries had no matching allow rule. All nine
Compose workloads require public image pulls or public build dependencies.

RepoTrial's frozen safety contract requires explicit denial of private, metadata,
and host destinations; it does not prohibit public egress. `DockerSbxProvider`
correctly supplied those mandatory deny rules but did not establish the
sandbox-scoped public allow required under the installed global default-deny.
The SBX runtime enforced its policy correctly; the missing allow was a RepoTrial
provider compatibility defect. Coverage is **9/9 Boot attempts**.

## One generic fix

The installed official CLI help proves that
`sbx policy allow network --sandbox <sandbox-id> "**"` is supported and that
deny rules override allow rules. The minimal fix therefore:

1. keeps every existing create-time mandatory `--deny-network` rule;
2. after successful sandbox creation and before ACTIVE/workload execution, adds
   one sandbox-scoped public allow rule;
3. probes the installed CLI for `policy allow network`, `--sandbox`, and `**`;
4. uses the existing whole-trial monotonic deadline for the allow operation;
5. force-cleans partial creation if policy installation fails, without allowing
   the exhausted trial deadline to block cleanup.

No Graph, Boot, Recovery, manifest, verifier, `SandboxProvider` interface, or
frozen contract changed.
