## Dominant-cause ruling

**Ruling: one dominant generic cause exists, with 3/3 qualifying attempts.**

The normalized retained signature is:

```text
phase = baseline Boot / Compose up
command = up
exit = 1
stderr = open <host-ext4-checkout>/artifacts/<run_id>/workspace/docker-compose.yml: no such file or directory
stdout_truncated = false
stderr_truncated = false
```

All three exact-SHA workspaces contain the selected root-relative Compose file
on the WSL host, and all three sandboxes were created successfully. The first
guest Compose command then received a host-side absolute artifact path that was
not present in the sandbox filesystem. It failed after crossing the target
workload execution boundary but before reading Compose input or starting any
target service. This is **Category A — same RepoTrial generic bug**,
specifically a host-to-guest Compose path mapping/command-construction defect.

This conclusion comes from the three non-truncated `up` stderr streams and their
matching command phase/exit, not from the high-level
`boot_recovery_stopped` label. There is no dissenting attempt and no
missing-environment signature. The evidence does not authorize a
repository-specific workaround, a recovery-context/environment correction, or
an inferred readiness correction. Task 3's bounded-recovery/missing-environment
entry gate is therefore not established by this Task 2 ruling; no later task was
started.
