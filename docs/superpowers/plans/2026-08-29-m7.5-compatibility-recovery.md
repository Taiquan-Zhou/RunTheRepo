# M7.5 Real-Repository Compatibility Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover generic Docker Compose Web App compatibility from retained real-repository evidence, then prove the result on the frozen canary and ten-repository cohort without changing RepoTrial's frozen architecture.

**Architecture:** Add a private Boot evidence boundary first, run three diagnostic repositories, and implement only the dominant generic cause demonstrated by those artifacts. Anticipated bounded corrections are a deterministic recovery evidence projection, pinned-workspace repository context, and official Compose readiness; none changes public state, Provider, report, Journey, or experiment contracts.

**Tech Stack:** Python 3.12, Pydantic v2, LangGraph, Typer, pytest, Docker Sandboxes v0.39.0, Docker Compose in the SBX guest.

**Spec:** `docs/superpowers/specs/2026-08-29-m7.5-compatibility-recovery-design.md`

## Global Constraints

- Base commit is `54481329c60b1a5fcb56650e246b0531583a1403`.
- Frozen manifest is `eval/real_repos.yaml`; repository order, URLs, commit SHAs, Compose paths, ports, and attribution rules must not change.
- No host Docker fallback, repository-specific workaround, model integration, PID claim, or daemon start/stop/restart/reset.
- Do not change `RunState`, `GraphState`, `SandboxProvider`, report/API/CLI semantics, Journey semantics, mutation semantics, or M5 KEEP/ROLLBACK decisions.
- `boot_compose()` remains the single shared baseline/candidate Boot implementation.
- Every behavior change uses RED -> GREEN -> REFACTOR with a recorded failing test before production edits.
- Each persisted stdout/stderr view is at most 32,000 UTF-8 bytes; all six views total at most 192,000 bytes; final Boot evidence JSON is at most 262,144 UTF-8 bytes.
- A canary success requires exact SHA, a non-empty deterministic required baseline Journey set, every required baseline Journey PASS and be persisted, completed report evidence, and successful cleanup; the canary gate is at least 2/3.
- Final release targets remain autonomous success `>=7/10`, meaningful convergence `>=5/10`, exact stop reasons `10/10`, and cleanup `100%`.
- If diagnostic evidence does not show one dominant generic cause across at least two canary repositories, stop after Task 2 and revise this plan from evidence.
