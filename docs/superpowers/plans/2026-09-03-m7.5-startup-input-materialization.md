# M7.5 Startup-Input Materialization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Materialize one narrowly defined missing `.env` inside each disposable
guest before Boot, without exposing host values or changing RepoTrial's frozen
orchestration and product contracts.

**Architecture:** A private `startup_inputs` module plans deterministic bytes
from the pinned host clone, omits every control-prefixed assignment under the
Owner-approved Option B policy, then verifies and exclusively creates the file
inside the already-created guest. Baseline and candidate paths call the same
module at their existing post-create/pre-Boot boundaries. No graph node,
checkpoint field, Provider method, public option, or host fallback is added.

**Tech Stack:** Python 3.12, asyncio, Pydantic-free frozen dataclasses,
`SandboxProvider.exec(argv)`, ruamel.yaml through the existing safe Compose
loader, pytest, Docker Compose, Docker Sandboxes.

**Spec:**
`docs/superpowers/specs/2026-09-02-m7.5-startup-input-materialization-design.md`

**Execution base:** `4300b844c2fc32180d2f7c2b7070b110ca6b3ab1`

## Global Constraints

- The Owner approved Option B on 2026-09-03: guest-file control assignments are
  omitted; existing host command-environment rejection remains unchanged.
- Never copy, synthesize, or export normalized `COMPOSE_*`, `DOCKER_*`,
  `DYLD_*`, `LD_*`, `PATH`, `HOME`, `PYTHONHOME`, `PYTHONPATH`, or
  `XDG_CONFIG_HOME` assignments.
- Normalize portable ASCII keys with `key.upper()` for policy checks; test
  lowercase variants such as `ld_preload`.
- Accept only clone-root `.env.sample -> .env`; the selected Compose may be the
  original root file or an accepted file in a child directory, but the verified
  clone root remains its explicit project directory. Maximum source size is
  65,536 bytes, assignment count 64, and logical line length 4,096 bytes.
- Never execute repository prose/scripts or read a host environment value.
- The host workspace and source Compose remain unchanged. The generated file is
  guest-only, mode `0600`, exclusive, bounded, and hash-verified.
- The generated root `.env` is both a service `env_file` and Compose project
  interpolation input; validate and hash the resolved Compose model before Boot.
- The verified guest clone root is the fixed Compose project directory for
  config, Boot, and observation, including after KEEP selects an accepted
  Compose file in a subdirectory.
- Unset every source-template key from the ambient guest environment before
  applying existing validated explicit Compose env assignments; use the same
  prefix for config, Boot, and Compose discovery in observation.
- A resolved model that is privileged, uses host networking, devices, an engine
  socket, or a bind source outside the verified guest clone is unsupported.
- Baseline and candidate reuse the same source/output hashes and policy. Their
  resolved Compose hashes are distinct audit values when an overlay changes the
  candidate.
- Materialization failure is fail-closed `UNSUPPORTED`; `managed_sandbox`
  cleanup still runs. No host Docker fallback and no daemon lifecycle command.
- Do not change LangGraph topology, `GraphState`, `RunState`, checkpoint, report,
  API/CLI, Journey, mutation, or KEEP/ROLLBACK semantics.
- TDD is mandatory: observe the intended RED before every production behavior.
- Real-SBX execution is serial, uses a trusted local fixture first, and ends with
  official empty inventory. Never start/stop/restart/reset the daemon.

class StartupInputUnsupported(RuntimeError):
    reason: str


@dataclass(frozen=True, slots=True)
class StartupInputPlan:
    compose_relative_path: str
    compose_config_hash: str
    source_relative_path: str
    target_relative_path: str

  and never source content.

  state.
