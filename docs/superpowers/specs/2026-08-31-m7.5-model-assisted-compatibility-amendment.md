# M7.5 Model-Assisted Compatibility Recovery Amendment

## Status and authority

Owner-approved amendment to
`2026-08-29-m7.5-compatibility-recovery-design.md` after the retained final
canary failed at unified HEAD `bf62cc72ca3b77e305312f4cc54ff88d49e2bbff`.

This amendment supersedes only the model-integration prohibitions in the
earlier compatibility-recovery design and WSL2 execution design, plus the
obsolete assumption that the three canary failures share one Boot cause. The
WSL2 environment, Docker SBX execution route, daemon-lifecycle ban, and every
other frozen product, safety, cohort, attribution, cleanup, and architecture
contract remain in force.

## Final product target

RepoTrial remains:

```text
public GitHub URL
-> exact pinned commit
-> disposable isolated Docker Compose workload
-> bounded model-assisted Journey/recovery planning
-> deterministic Journey verification
-> bounded apply/boot/replay/verify KEEP-or-ROLLBACK experiments
-> evidence-backed report
-> forced cleanup
```

The model proposes bounded typed data. It never decides functional success,
experiment acceptance, safety, cleanup success, or report truth.

The first three frozen repositories remain Umami, Listmonk, and

## Proven canary causes

The final canary is heterogeneous and must not be treated as one generic Boot
failure:

1. **Umami — Docker-data exhaustion.** The 2,048 MiB policy maps to root 1 MiB,
   Docker data 1,791 MiB, and workspace 256 MiB. PostgreSQL failed with
   `No space left on device`. The allocation arithmetic is correct; a minimum
   successful total/balance is not yet proven.
2. **Listmonk — readiness plus empty Journey set.** `compose up -d` is followed
   immediately by `compose ps`; the current recovery `wait` destroys the
   sandbox before sleeping and creates a new sandbox on the next attempt, so it
   cannot wait for the same stack. The repository has no declared RepoTrial
   Journey and the no-model path returns an empty set.
3. **changedetection.io — observation boundary.** Boot passed, then
   `ObservationCollectionError` was flattened without enough collector/phase
   evidence to identify the exact failing boundary.
4. **Model path — generic timeout/schema defects.** Both Journey and recovery
   model calls have a 100 ms planner deadline while the HTTP adapter permits a
   10 second request. A real local 4B model produced a valid recovery response
   in about 0.7 seconds. Ollama `0.20.7` returned an exact HTTP 500 for the
   current Journey JSON schema, while JSON-only fallback was not consistently
   policy-valid. These facts justify calibration and focused TDD, not a broad
   DSL or verifier change.

## Model trust and determinism contract

### Authority

The model receives only bounded, redacted repository documentation and bounded,
redacted runtime evidence already admitted by existing policy. README, logs,
and model output remain untrusted data.

Model output must pass, in order:

1. bounded transport decoding;
2. strict schema validation with unknown fields rejected;
3. existing Journey or Recovery policy validation;
4. existing authority and tool allowlists.

Failure at any layer is fail-closed: Journey planning returns an empty set or
recovery returns `stop`. No default `GET /`, shell command, host action, secret,
or permission fallback is synthesized.

### Deterministic decision boundary

A model-planned Journey becomes ordinary immutable Journey data only after the
four validation layers pass. Before workload replay, the exact normalized
Journey JSON is written to a private no-overwrite canonical Journey artifact
with its SHA-256. Immediately before baseline and candidate replay, RepoTrial
re-canonicalizes the in-memory Journey objects and requires an exact hash match
with that artifact. Baseline and every candidate therefore replay the same
persisted Journey definition. Only deterministic Journey verifiers decide PASS
or FAIL, and only the existing deterministic experiment engine decides KEEP or
ROLLBACK. The private artifact does not change the public report schema.

No model call may occur inside an assertion verifier or after a candidate
Journey has begun in order to reinterpret its result.

### Runtime boundary

Ollama and the selected Qwen model are development/M7.5 evaluation
infrastructure, not mandatory package dependencies. Existing optional CLI/API
model endpoint semantics remain unchanged. The final execution ledger records:

- RepoTrial HEAD and manifest hash;
- model endpoint class, model name, full model digest, and model runtime
  version;
- structured-schema mode or documented bounded fallback mode;
- cold/warm calibration latency and configured planner deadline;
- persisted normalized Journey hash per repository.

The current test model is official `qwen3:4b-instruct`, observed digest prefix
`0edcdef34593`. Before adapter behavior changes, update to the current official
stable Ollama release and repeat the exact RecoveryAction and Journey schema
probes. A fallback correction is eligible only if the exact incompatibility is
reproduced on that calibrated runtime.

## Private diagnostic evidence

Diagnostic evidence must not alter `RunState`, `GraphState`, checkpoints, the
public report schema, or public CLI/API semantics.

### Model-planning attempts

The validated private run evidence directory may contain
`baseline-model-attempt.jsonl`; recovery entries are written inside the already
claimed Boot attempt directory. They record only bounded metadata:

- schema version, purpose (`journey` or `recovery`), and start/terminal phase;
- monotonic elapsed time and one canonical outcome from `success`,
  `planner_timeout`, `transport_error`, `http_error`, `response_too_large`,
  `structured_response_invalid`, `policy_rejected`, or `adapter_error`;
- prompt-input hashes and byte lengths, never raw README/log content;
- schema hash, normalized accepted-output hash, Journey count, and rejection
  reason code;
- no token, credential, endpoint query, raw model output, or raw target output.

Existing `plan_journeys()` and `propose_recovery()` behavior remains available
without an evidence destination. Graph uses a private shared implementation
that enables evidence inside the claimed attempt directory. Evidence write
failure is fail-closed and still passes through managed sandbox cleanup.

Model adapter failures expose one credential-free bounded reason code from the
closed set `transport_error`, `http_error`, `response_too_large`, and
`structured_response_invalid`. Planner-owned deadline expiry is recorded
separately as `planner_timeout`; a schema-valid proposal rejected by existing
Journey/Recovery policy is `policy_rejected`. Unknown third-party adapter
exceptions become `adapter_error` without inspecting exception text. Model and
runtime identity remains in the external frozen execution ledger, not in the
per-call artifact or `ModelAdapter` protocol. These names are the artifact's
canonical `outcome` values; there is no second terminal-class vocabulary.

### Observation attempts

The claimed attempt directory may contain append-only private
`baseline-observation-attempt.jsonl`. Each collector boundary writes a start
event and exactly one success/failure event with:

- schema version, sequence, collector enum, operation phase, and reason code;
- argv SHA-256 and argv item count, not raw dynamic output;
- exit code or sanitized provider exception class;
- stdout/stderr UTF-8 byte lengths, bounded hashes, and truncation flags;
- serialization and atomic-persistence phases;
- no raw environment value or unredacted collector output.

The original provider exception continues to propagate where current contracts
require it. The diagnostic artifact must reveal the collector and phase without
turning private exceptions into public report details.

## Bounded corrections

### 1. Model planner compatibility

- Replace the contradictory 100 ms planner deadline with one explicit bounded
  timeout calibrated from the current runtime's measured latency and recorded
  in the execution fingerprint. It remains independent of Provider state.
- Preserve cancellation and observation of model tasks.
- Describe the existing allowed Journey DSL values in the prompt/schema so a
  small model can produce policy-valid data; do not expand the DSL.
- Add a narrowly classified adapter fallback only if the calibrated current
  runtime reproduces an explicit schema-capability incompatibility. Auth,
  quota, rate-limit, model-not-found, network, and generic server errors never
  trigger fallback.

### 2. Compose readiness

The installed guest Compose has already proven official support for:

```text
docker compose ... up -d --wait --wait-timeout 60
```

Use this shared trusted readiness command for baseline and candidate Boot while
retaining provider per-command and whole-trial monotonic deadlines. Continue to
collect deterministic `ps` and `logs`. Remove deterministic generation and
execution of the current dead `wait` recovery path; an externally supplied
`wait` action fails closed for compatibility.

### 3. Observation diagnosis and correction

Add the private attempt ledger first, rerun changedetection.io once as
diagnostic-only, and identify the exact collector/phase. Implement at most one
generic observer correction proven by that evidence. If the failure is target
specific, unsupported, or remains insufficiently evidenced, preserve the
failure and do not patch by guess.

### 4. Disk calibration

Use non-destructive trusted fixture/canary calibration only:

- C0 varies the current root/Docker/workspace balance at the same total to test
  whether allocation ratio alone is causal;
- C1 increases the total policy while retaining official three-way accounting
  until Umami Boot either succeeds or a bounded unsupported result is proven;
- every attempt must preserve exact SHA, no host fallback, forced cleanup, and
  empty final inventory.

One Umami result does not authorize a global default change. Changing the
public/default `SandboxPolicy.disk_mb` is a separate C2 ruling requiring cohort
evidence that the new bounded default is generally necessary and does not
weaken the frozen hard bound. Disk arithmetic and environment mapping remain
unchanged unless their own tests prove a defect.

## Architecture impact limit

Allowed changes are confined to:

- private model/observer diagnostic evidence;
- `OpenAICompatibleModelAdapter` compatibility classification;
- existing Journey/recovery planner timeout and bounded prompt;
- shared `boot_compose()` readiness behavior;
- one evidence-proven observer correction;
- focused tests, fixtures, execution ledger, and documentation.

The task stops for Owner ruling if it requires changes to:

- LangGraph topology;
- M5 engine contract or KEEP/ROLLBACK semantics;
- M6 RunState/checkpoint semantics;
- M7 public report/API/CLI semantics;
- Journey DSL or deterministic verifier semantics;
- mutation engine architecture;
- `SandboxProvider` interface;
- frozen manifest or repository-specific branches.

## Validation and completion

Every behavior change follows RED -> GREEN -> REFACTOR, independent focused
review, controller diff review, focused tests, Ruff lint/format, strict mypy,
coverage at least 85%, pre-commit, `git diff --check`, and a fresh full-test run
with zero regressions relative to the accepted environment baseline.

Real execution uses only the currently healthy SBX daemon; this plan never
starts, stops, restarts, or resets it. Every diagnostic and metric attempt must
record cleanup and end with empty SBX inventory.

M7.5 closes only when one final production HEAD and one frozen model/runtime
fingerprint complete the frozen ten-repository cohort and meet every release
threshold above. Documentation then describes the optional local-model setup,
the known PID limitation, and observed compatibility without claiming global
safety.
